# KOROLKO — тестовый Telegram Mini App

Демо-витрина магазина украшений ручной работы (браслеты, брелки и др.) в виде Telegram-бота с мини-приложением
(Telegram WebApp). **Реальная оплата не подключена** — оформление заказа
имитируется и присылается ботом в чат как подтверждение.

Все файлы лежат плоско в корне репозитория — ничего распаковывать не нужно,
просто загрузите папку целиком на GitHub.

## Состав репозитория

```
main.py           — Flask-сервер: мини-апп, Telegram-бот (webhook) и API админ-панели
index.html        — интерфейс мини-приложения (каталог, корзина, оформление заказа)
admin.html        — админ-панель (товары: добавление/редактирование/удаление/фото;
                     заказы: просмотр, статусы, сообщения покупателю)
products.json     — каталог товаров (админка читает и пишет в этот файл)
orders.json       — оформленные заказы (создаётся автоматически при первом заказе)
uploads/          — загруженные из админки фотографии товаров
madebar.html      — Made Bar: конструктор украшений из бусин (мини-апп, страница /madebar)
madebar.py        — подключение Made Bar к main.py, раздача страницы и картинок бусин
bead_api.py       — публичный API конструктора: каталог бусин, заказ сборки, уведомление в Telegram
bead_admin.py     — API админки Made Bar: бусины (CRUD, загрузка PNG), заказы сборок, статусы
bead_art.py       — рисует картинки бусин в SVG (стартовый каталог работает без загрузки файлов)
seed_beads.py     — стартовый каталог (55 бусин), создаётся один раз в пустой базе
models.py         — модели базы данных (SQLAlchemy): Bead, CustomOrder
madebar_config.py — настройки Made Bar: цена основы, лимит бусин
requirements.txt  — python-зависимости
Procfile          — команда запуска для Render
render.yaml       — опциональный blueprint для Render
```

## 1. Создайте бота

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. `/newbot` → задайте имя и username.
3. Сохраните выданный **токен** (`BOT_TOKEN`).

## 2. Загрузите код на GitHub

Создайте новый репозиторий и загрузите в него все файлы из этой папки
(в корень, без вложенных папок).

## 3. Разверните на Render

1. На [render.com](https://render.com) → **New → Web Service**.
2. Подключите ваш GitHub-репозиторий.
3. Настройки сборки Render определит автоматически (`Procfile`), либо укажите вручную:
   - **Build command:** `pip install -r requirements.txt`
   - **Start command:** `gunicorn main:app --bind 0.0.0.0:$PORT`
4. В разделе **Environment** добавьте переменные:
   - `BOT_TOKEN` = токен из BotFather
   - `ADMIN_PASSWORD` = придумайте пароль для входа в админ-панель
   - `ADMIN_CHAT_ID` = ваш Telegram ID (узнать можно, например, у бота
     [@userinfobot](https://t.me/userinfobot)). Только этому пользователю бот
     будет присылать по `/start` дополнительную кнопку со ссылкой на
     `/admin`. Можно указать несколько ID через запятую: `111111,222222`.
   - `DATABASE_URL` = строка подключения к PostgreSQL (нужна для Made Bar,
     см. раздел «Made Bar» ниже).
5. Дождитесь деплоя. Render сам передаёт в контейнер `RENDER_EXTERNAL_URL`
   (например `https://korolko-bot.onrender.com`) — приложение использует его
   как адрес вебхука и адрес мини-аппа автоматически.
   Если хотите задать адрес вручную, добавьте переменную `WEBHOOK_URL` с
   полным https-адресом вашего сервиса (без слэша в конце).

После первого успешного старта приложение само установит вебхук Telegram —
никаких дополнительных команд выполнять не нужно.

## 4. Проверьте бота

1. Откройте вашего бота в Telegram.
2. `/start`.
3. Нажмите кнопку **«👑 Открыть KOROLKO»** — откроется каталог.
4. Добавьте товар в корзину, нажмите **«Оформить заказ»**, заполните имя,
   телефон и (по желанию) комментарий, нажмите **«Подтвердить заказ»**.
   Бот пришлёт покупателю подтверждение в этот же чат, а всем администраторам
   из `ADMIN_CHAT_ID` — уведомление о новом заказе.
5. Если ваш Telegram ID указан в `ADMIN_CHAT_ID`, под тем же сообщением
   появится вторая кнопка **«Панель администратора»** (открывается как
   Telegram Mini App, так же как и сам магазин) — её видите только вы,
   обычные пользователи получают лишь кнопку «👑 Открыть KOROLKO».

## 5. Админ-панель

Откройте `https://ваш-адрес.onrender.com/admin` в браузере (телефон или компьютер)
и войдите с паролем из `ADMIN_PASSWORD`.

В панели две вкладки:

**Товары**
- добавлять новые товары (название, категория, цена, размеры, описание);
- загружать фото товара с устройства — при нажатии на область фото открывается
  обычный системный выбор файла (галерея, файлы, при желании — камера);
- редактировать и удалять существующие товары.

Если фото не загружено, товар в каталоге показывается с цветной плашкой
(можно выбрать один из 6 оттенков) — как было в исходной демо-версии.

Каталог (`products.json`) сейчас содержит несколько демо-товаров
(брелок и браслет) — просто пример.
Отредактируйте или удалите их и наполняйте витрину своими товарами через `/admin`.

**Заказы**
- список всех оформленных заказов: состав, сумма, имя, телефон, комментарий
  покупателя, время оформления;
- если заказ сделан из Telegram — прямо из карточки заказа можно написать
  покупателю сообщение, которое бот отправит ему в чат (обсудить доставку,
  уточнить детали); если у покупателя есть публичный username, рядом
  появится и ссылка `@username` для перехода в личный диалог;
- если у покупателя нет username или заказ оформлен вне Telegram — можно
  позвонить по указанному телефону (кнопка-ссылка `tel:`);
- у каждого заказа есть статус (Новый / Связались / Выполнен / Отменён),
  который можно менять прямо из списка; счётчик новых заказов виден
  на вкладке «Заказы».

### Постоянное хранилище (важно)

На **бесплатном** плане Render диск контейнера не сохраняется между
рестартами и редеплоями — это значит, что товары и заказы, добавленные через
`/admin` и мини-апп (файлы `products.json` и `orders.json`), и загруженные
фото (`uploads/`) **пропадут** при следующем деплое или после длительного
простоя (см. ниже про «засыпание»).

Варианты решения:
- Для теста — этого достаточно, просто добавляйте товары заново после деплоя.
- Для постоянной работы — подключите платный **Persistent Disk** в настройках
  Render (или раскомментируйте блок `disk:` в `render.yaml`) и укажите путь
  монтирования равным корню проекта, чтобы `products.json`, `orders.json`
  и `uploads/` сохранялись между рестартами.

## Made Bar: конструктор украшений

Покупатель собирает браслет или чокер из бусин прямо в мини-аппе: нажимает на
бусину в лотке, она «перелетает» на нить, сверху считается длина, внизу цена
(основа + бусины). Нажатие на бусину на нити убирает её (есть кнопка «Вернуть»),
корзина очищает нить целиком. Потом заполняется имя, телефон, доставка или
самовывоз, и заказ уходит мастеру.

**Как открыть:** кнопка «🧵 Собрать украшение (Made Bar)» под сообщением бота
по `/start`, баннер в магазине или адрес `https://ваш-адрес.onrender.com/madebar`.

**Что получает мастер:** сообщение в Telegram всем из `ADMIN_CHAT_ID` с готовым
рецептом сборки (бусины по порядку слева направо, размеры, список закупки,
сумма). Тот же рецепт виден в админке: вкладка **Made Bar → Заказы сборок**
(есть статусы Новый / Собран / Отменён и кнопка «Скопировать»).

### Подключите базу данных (один раз)

Made Bar хранит бусины и заказы в базе данных, а не в JSON-файлах.

1. На Render: **New → PostgreSQL**, создайте базу.
2. Откройте её страницу и скопируйте **Internal Database URL**.
3. В вашем Web Service → **Environment** добавьте переменную
   `DATABASE_URL` с этим значением и сохраните (сервис перезапустится).

Таблицы создаются сами при старте, а в пустую базу автоматически добавляется
стартовый каталог из 55 бусин (камни, серебро, 33 буквы, разделители, подвески).
**Цены и размеры в нём примерные: поправьте их в админке.**

> Без `DATABASE_URL` приложение запустится на временном SQLite-файле. Для теста
> это нормально, но на Render он стирается при каждом деплое: пропадут и заказы
> сборок, и ваши правки каталога. Бесплатная база Render ограничена по сроку
> жизни, актуальные условия смотрите на странице тарифов. Для постоянной работы
> берите платный тариф или любой внешний PostgreSQL (например Neon или
> Supabase): подойдёт любая строка подключения вида `postgresql://…`.

### Настройки (необязательно)

| Переменная            | По умолчанию | Что делает                                      |
|-----------------------|--------------|-------------------------------------------------|
| `MADEBAR_BASE_PRICE`  | `700`        | Стоимость основы (шнурок + застёжка), ₽         |
| `MADEBAR_MAX_BEADS`   | `30`         | Максимум бусин на одной нити                    |
| `MADEBAR_RATE_LIMIT`  | `6`          | Заказов с одного адреса за 10 минут (от спама)  |

Цена основы хранится в одном месте и подтягивается и в страницу, и в проверку
на сервере. Итоговую сумму всегда считает сервер, подделать её в браузере нельзя.

### Управление бусинами в админке

Откройте `/admin` → вкладка **Made Bar** → **Бусины**:

- **«+»** добавляет бусину: название, категория (выбор из существующих или
  новая), цена, диаметр в мм (от него зависит размер бусины на нити),
  картинка (загрузка PNG/WebP до 2 МБ или ссылка `https://`);
- тумблер **«Нет в наличии»** мгновенно скрывает бусину из конструктора;
- **«Изменить»** меняет цену, размер, картинку, порядок;
- **«Удалить»** удаляет бусину (если она уже есть в заказах, админка предупредит;
  для временного скрытия лучше тумблер).

**Порядок:** чем меньше число в поле «Порядок», тем левее бусина в своей
категории. Порядок вкладок-категорий в конструкторе определяется по самой
первой бусине каждой категории.

**Картинки бусин.** Лучше всего прозрачный PNG, примерно квадратный, бусина
по центру. Встроенные картинки стартового каталога рисуются кодом
(`bead_art.py`) и не пропадают никогда. А вот загруженные вами файлы лежат в
`uploads/`, и на бесплатном Render они пропадают при деплое (см. «Постоянное
хранилище» ниже). Поэтому либо подключите диск, либо храните картинки на
внешнем https-хостинге и вставляйте ссылку.

## Новые возможности покупателя

- **Профиль** (иконка человечка в шапке) — история заказов покупателя со
  статусами (Новый / На связи / Выполнен / Отменён). Пока заказ не взят в
  обработку (статус «Новый»), под ним есть кнопка **«Отменить заказ»**.
- **Избранное** (иконка сердечка в шапке) — покупатель нажимает на сердечко
  на карточке товара или на странице товара, чтобы сохранить его в
  избранное, и открывает список избранного отдельной вкладкой. Хранится
  локально на устройстве покупателя.
- **Уведомления** — при добавлении в корзину/избранное, отправке заказа на
  обработку и его отмене показывается всплывающее уведомление снизу экрана.

## Важно про Render free-план

Бесплатный инстанс на Render засыпает при отсутствии трафика и просыпается
несколько секунд по первому запросу — это нормально для теста, при желании
позже можно перейти на платный план без засыпания.

## Локальный запуск (по желанию)

```bash
pip install -r requirements.txt
export BOT_TOKEN=your_token
export WEBHOOK_URL=https://ваш-туннель.example  # например ngrok
python main.py
```

Для локального теста без публичного домена вебхук не установится —
проще всего сразу тестировать после деплоя на Render.
